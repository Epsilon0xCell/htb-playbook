# Module: Web and API Depth

Run on signal, not as a blanket sweep. Indexed by OWASP WSTG categories and the API Security Top 10 (2023); cite test IDs in your notes rather than pasting prose.

1. Map before touching: crawl through Burp or ZAP, extract JS files and endpoints, check robots.txt, sitemap, and well-known paths.
2. Artefact hunt, early, cheap, high yield: `.git/`, `.env`, backup files (`.bak`, `.old`, archive suffixes on known files), `swagger.json` and `openapi.yaml`, Postman collections, source maps, debug endpoints. If source is obtained, go to step 10 now.
3. Fingerprint precisely: server, framework, CMS, and version from headers, error pages, favicon hash, and cookie names. CMS-specific enumeration only after the fingerprint confirms the CMS.
4. Auth and session: default and anonymous first, then registration and logic flaws, password-reset token predictability and leak (host header, referer, token not expiring or reusable), session fixation, cookie flags, JWT (step 6), MFA bypass via response manipulation or missing step enforcement.
5. Authorisation, with 2 accounts whenever registration is possible: IDOR and BOLA on every object ID (sequential, UUID, encoded), function-level checks (a user token against admin endpoints), method switching, parameter pollution. Automate replay with an Autorize-class tool; confirm manually.
6. JWT and OAuth: decode the token; `alg:none`; RS256 to HS256 confusion with the public key as the HMAC secret; `kid` injection (path or SQL); weak-secret cracking (hashcat JWT mode) on a small curated list first; `jwk` and `jku` injection. OAuth: `redirect_uri` looseness, missing `state`, missing PKCE, token leak via referer or an open redirect chain, grant-type abuse.
7. API-specific: undocumented endpoints via JS plus wordlists; old versions (`/v1` when `/v2` is current); mass assignment (role, isAdmin, balance fields in PUT and PATCH bodies); excessive data exposure; GraphQL introspection, field-level authorisation, batching and alias-based bypass; SSRF on any URL, webhook, or import parameter; business-flow abuse (coupon, price, negative quantity).
8. Race conditions and smuggling, Hard and above or on any limit signal: one-time-use flows (coupon, OTP, vote, withdraw) via the single-packet attack. Request smuggling only when a front and back pair exists: timing-based desync probes first. Cache poisoning or deception when a cache is fingerprinted.
9. Injection, ordered by observed signal, not alphabetically: error or behaviour difference points to SQLi (manual confirm first, then sqlmap with tamper only on the confirmed parameter); reflected or stored context points to XSS or DOM; template syntax reflected points to SSTI; a file-path parameter points to LFI and traversal, then log poisoning or a PHP filter chain; upload points to extension, MIME, magic-byte, and parser differentials; XML input points to XXE; command-shaped parameters point to blind command injection via timing or an out-of-band pingback.
10. Source review, mandatory when source or config is obtained, and the first move at Hard and above after any file-read primitive: read in order, routes and entry points, auth middleware, the sink list (SQL construction, eval and exec, deserialisation, file operations, crypto calls), secrets in config and history, dependency versions against known vulnerabilities. Record every check the code claims to do and test whether it is actually enforced. The pattern on record: a logic flaw in a custom privileged component.

Tools named here: Burp, ZAP, CMS scanners of the WPScan class, Autorize-class replay, sqlmap, hashcat (JWT mode).
